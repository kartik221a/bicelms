# MASTER PROJECT PROMPT: COMPLETE LMS PLATFORM

You are a senior full-stack engineer, software architect, UI/UX designer, security engineer, and product developer.

Your task is to design, architect, and develop a complete, production-ready Learning Management System (LMS) for a professional coaching institute.

This is NOT a simple course-selling website. Build a complete educational platform where instructors can publish courses, students can purchase them, and enrolled students can access protected educational content through their personal dashboards.

The entire project must be developed as ONE unified Next.js application.

Do not split the frontend, backend, admin panel, or API into separate applications.

### Backend

# 7. VIDEO SECURITY AND PROTECTED PLAYBACK

This is one of the most important requirements.

Students must watch purchased course videos directly on the website.

Do not provide direct video download links.

Implement a layered video protection system.

### Required protections

1. Authenticated playback.
2. Server-side enrollment verification.
3. Signed, expiring playback URLs or tokens.
4. Short-lived playback authorization.
5. Secure video delivery.
6. Prevent direct access to private media URLs.
7. No video URLs exposed in public API responses.
8. No download buttons.
9. Disable player download controls where supported.
10. Restrict playback to authorized lessons.
11. Validate authorization on every playback request.
12. Rate limiting on playback authorization endpoints.
13. Session/device tracking.
14. Configurable concurrent session limits.
15. Dynamic student watermark overlay.

### Dynamic Watermark

Display a subtle, moving watermark over the video.

Include:
- Student name.
- Student email (partially masked where appropriate).
- Student ID or unique identifier.

The watermark should move periodically to make simple cropping more difficult.

### Video Player

Build a professional video player with:

- Play/pause.
- Volume control.
- Playback speed.
- Fullscreen.
- Picture-in-picture where appropriate.
- Quality selection when supported.
- Timeline.
- Current timestamp.
- Duration.
- Resume playback.
- Captions/subtitles where available.

Disable right-click on the video player as a deterrent, but do not treat this as a security mechanism.

### Important Storage Architecture

Cloudinary is the initial storage provider.

However, design the video delivery system around a VideoProvider abstraction.

The application should support future migration to:
- Cloudinary.
- Hostinger storage.
- Other compatible video hosting/CDN solutions.

IMPORTANT TECHNICAL SECURITY REQUIREMENT:

Ordinary private files on Cloudinary with hidden URLs are NOT sufficient protection.

Use authenticated/signed delivery and ensure the chosen delivery configuration actually supports the required access restrictions.

Prefer private HLS streaming with protected manifests and segments where supported.

Do not claim that browser playback makes downloading or screen recording impossible.

If the selected Cloudinary configuration cannot securely support protected streaming, clearly identify the limitation and design the VideoProvider interface so a proper protected streaming provider can be integrated later.

Never silently downgrade security.

# 9. RAZORPAY PAYMENT INTEGRATION

Implement complete Razorpay integration.

Features:
- Course purchase.
- Secure order creation.
- Payment checkout.
- Payment verification.
- Payment failure handling.
- Webhook handling.
- Refund status tracking.
- Payment history.
- Order history.
- Invoice/receipt generation.
- Coupon support.

### Payment Flow

1. Student selects a course.
2. Server checks course availability and current price.
3. Server creates a Razorpay order.
4. Frontend opens Razorpay Checkout.
5. Student completes payment.
6. Server verifies the payment signature.
7. Razorpay webhook independently confirms payment status.
8. Create enrollment only after verified payment.
9. Show course in student dashboard.
10. Send purchase confirmation.

Prevent:
- Duplicate orders.
- Duplicate enrollments.
- Client-side price manipulation.
- Fake payment-success requests.
- Webhook replay attacks.
- Unauthorized refunds.

Support:
- INR.
- Indian payment methods supported by Razorpay.

Never expose Razorpay secret keys in frontend code.
